# Computation-only TTFT methodology

The primary metric is llama.cpp `timings.prompt_ms`: slot input processing start through first token sampling, including fresh visual encoding and language prefill in b11577. This is model-runtime wall time with CPU/GPU scheduling and synchronization, not a sum of GPU kernel durations. Slot admission queueing, HTTP, weight loading, client JPEG preparation, video decoding and some input parsing are outside this interval. Concurrent execution can still include scheduling/batching waits inside the interval.

Source: [server-context.cpp](https://github.com/ggml-org/llama.cpp/blob/b11577/tools/server/server-context.cpp) (`update_prompt_start`, image encoding/processing, `update_prompt_last` at first token); [server-common.h](https://github.com/ggml-org/llama.cpp/blob/b11577/tools/server/server-common.h) (prompt timestamps); [server-common.cpp](https://github.com/ggml-org/llama.cpp/blob/b11577/tools/server/server-common.cpp) (JSON timing serialization). The first token comes from final prefill logits. `prompt_ms + predicted_ms` is full-answer computation, covering subsequent decoding. First visible SSE text is a different timestamp, retained as original evidence. The previous [HTTP methodology](request-latency-methodology-archive.md) and [report](request-latency-archive-zh.md) are archived.

Every new formal condition has two randomized-order blocks of24 paired distinct source questions (IDs0–47), preceded by eight separate warmup questions per block (112–119). Disjoint eight-question pilot sets (64–71) do not substitute for formal measurements. Greedy temperature0, seed20261013; `cache_prompt=false`, RAM prefix cache and idle-slot cache disabled; actual `cache_n=0` is checked. Failed/missing records remain in the denominator. All language layers and the visual encoder use CUDA, verified from startup logs.

Original small-model controls: four threads, 2048 logical batch, 512 microbatch, flash attention, 8192 context per slot, four slots except the explicit single-slot comparison, 32 output tokens with EOS suppressed. The original46 conditions and all3024 requests remain untouched; compute summaries are rederived from saved internal timers.

New MiniCPM-o2.6: original author language Q4_K_M weights; F16 visual projector or mixed Q8_0 / Q4_K_M derived from that F16 source. Fallback affects27/455 and163/455 tensors respectively, so these are not uniformly8-bit or4-bit visual models. One slot, context4096, batch2048/microbatch512, four threads unless labeled eight-thread case, EOS allowed and max4 output tokens. Full-answer durations are not comparable across output budgets. Source/derived SHA256, commands and revisions: `data/minicpm-artifacts.json`.

Each request reruns vision and language; no feature/prefix reuse or split deployment. StreamingBench uses paired source IDs; last frame for one-frame input, corresponding last four for four-frame input. Compact prompts preserve question/options but shorten instructions. Area budget is the square root of maximum pixel area, preserving aspect ratio and rounding dimensions down to multiples of28. JPEG quality95. Processor resizing/cropping can make token counts discontinuous. The separate224-square synthetic color task varies rectangle position/color deterministically; its latency does not establish real video QA latency or general accuracy.

Mean CIs use seeded2000-replicate bootstrap; concurrent main comparisons resample whole waves. Paired differences use source IDs and are descriptive, especially at few independent waves/blocks. Median, p95 and standard deviation are in CSV. No monotonic ordering is imposed. The baseline is the observed minimum among tested text candidates, not a global optimum.

GPU contention is a separate FP16 GEMM worker, not a guaranteed compute fraction or hardware-equivalent GPU. Existing power/clock settings are preserved. Users share one weight copy; simultaneous waves are closed-loop, not production arrival rates. Length controls use actual total input tokens. Original token-roundtrip mismatches remain visible; only `inputs_exact` strictly matches token counts.

Historical b11516 Vulkan MiniCPM has125 observations per condition, without a proven independent warmup protocol. Preserve all125 and report drop-first sensitivity separately. LLaVA-Video NF4 timers measure cached-feature/prefix language answers with CUDA synchronization, not first tokens or complete fresh vision inference; do not sum IO-containing cache/prefix timers into TTFT. GRACE codec timings are non-LLM computation in an appendix. Missing Liquid_V1_7B/DCVC computation remains missing.
